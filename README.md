## 2. Тема проекта

Распределённая система мониторинга состояния и местоположения личного состава с иерархическим управлением по уровням подразделений (отделение → взвод → рота → батальон).

Каждый боец носит трекер: определение позиции по ГНСС, съём физиологических показателей через АЦП (пульс, температура, SpO₂, показатель стресса), передача телеметрии по основному каналу MQTT(Wi-Fi)/GSM/Zigbee/LoRaWAN(обговаривается) с автоматическим переходом на резервный канала. Командир любого уровня видит в мобильном приложении состояние и местоположение подчинённых — с декомпозицией по своей ветке иерархии и без доступа к соседним. Аутентификация — по идентификационному номеру военнослужащего и паролю.

Физическая периферия эмулируется: реализуются условные драйверы модулей с единым интерфейсом (`mock` / `hardware`), математические модели генерации правдоподобных данных и алгоритмы объединения показаний.

**Архитектурный принцип, определяющий разделение ответственности:**
- устройства **только передают данные** и принимают команды уровня устройства — бизнес-логики подразделения на них нет;
- устройства взаимодействуют между собой и с сервером; **мобильное приложение — отдельный слой, работающий исключительно через REST API** и никогда не подключающийся к устройству напрямую;
- вся бизнес-логика (композиция подразделений, агрегация состояний, правила алертов, права доступа) — на сервере и в приложении.

## 3. Задачи, решаемые в ходе работы

**Встраиваемая часть (Linux, С++23)**
1. Разработка условных драйверов периферийных модулей (ГНСС, АЦП/Цифровые датчики, радиомодем, GSM-модем, GPIO) с абстрактным интерфейсом и двумя взаимозаменяемыми реализациями — эмуляция и реальное железо при крайней необходимости (Предлагается модульная архитектура, в которой будет отдельный телеметрический модуль, реализованный на микроконтроллере STM32 с операционной системой реального времени, эмуляция RPi при этом остаётся, интерфейсом связи предлагается UART/USB) 
2. Построение математических моделей: модель перемещения бойца по сценариям с эмуляцией HDOP и потерь сигнала; модель физиологии, связанная с моделью нагрузки, с синтезом сырого сигнала фотоплетизмограммы и восстановлением ЧСС из него.
3. Реализация алгоритмов объединения данных: фильтр Калмана по позиции с отбраковкой выбросов, счисление пути при потере ГНСС, кросс-валидация физиологических показателей с оценкой достоверности, дедупликация пакетов между каналами.
4. Расчёт условного показателя состояния здоровья по документированной формуле.
5. Реализация двух каналов связи с автоматическим переключением, экспоненциальным backoff и возвратом на основной канал; шифрование полезной нагрузки AES-GCM для канала без TLS.
6. Механизм store-and-forward: буферизация телеметрии при отсутствии связи с приоритетами и выгрузкой без дублей и пропусков.
7. Локальный диагностический REST-интерфейс с возможностью инжекции событий и искусственного отключения каналов для тестирования.

**Серверная часть (Python / FastAPI / PostgreSQL / MQTT)**
8. Проектирование схемы данных: иерархия подразделений, личный состав, устройства и история их привязок, временной ряд телеметрии, алерты, команды, журнал аудита.
9. Реализация модели рекурсивной видимости по дереву подразделений и разграничения прав для шести ролей — с отказом и записью в аудит при попытке доступа к чужому поддереву.
10. Построение ingest-конвейера: приём телеметрии из MQTT и из GSM-шлюза, валидация, дедупликация, запись истории и корректная обработка пакетов «из прошлого» из буфера устройства.
11. Реализация агрегации состояния подразделений со свёрткой статуса вверх по иерархии и кэшированием сводок.
12. Разработка конфигурируемого движка правил алертов с дебаунсом, квитированием и закрытием (SOS, отсутствие пульса, критические показатели, выход из геозоны, отставание от подразделения, потеря связи, разряд батареи и др.).
13. Разработка REST API и потока событий реального времени (WebSocket с SSE-фолбэком), публикация OpenAPI-спецификации.
14. Реализация аутентификации и защиты: JWT с обновлением, хеширование паролей, ограничение частоты запросов, блокировка после серии неудачных попыток, TLS для REST и MQTT, ACL брокера по устройствам.
15. Нагрузочное тестирование конвейера приёма телеметрии с отчётом.

**Мобильное приложение (Java, Android SDK, Android Studio)**
16. Разработка единого приложения, адаптирующего интерфейс и объём данных под роль и позицию пользователя в иерархии.
17. Реализация экранов: сводка подразделения, дерево подразделений с агрегатами, карта с позициями и треками, карточка бойца с историей показателей и расшифровкой оценки состояния, лента алертов, управление составом, настройки.
18. Подключение потока реального времени с переподключением и фоновым сервисом; отправка команд устройствам через сервер.
19. Реализация офлайн-режима на локальной БД: отображение последних известных данных с явной индикацией их давности и очередь отложенных действий с досылкой при появлении сети.
20. Настройка push-уведомлений с раздельными каналами по критичности и переходом к соответствующему бойцу или алерту.
21. Разработка дизайн-системы «приборная панель» и её реализация: три темы (день, приборная, светомаскировка), избыточное кодирование статусов, плотная табличная вёрстка, стилизация карты под топооснову, доступность и работа в перчатках.

**Общее**
22. Развёртывание стенда одной командой (`docker compose up`): брокер, БД, сервер, N эмулируемых трекеров/радиоканалов.
23. Автоматизация проверок: линтеры, юнит- и интеграционные тесты, сборка APK и образов в CI.
24. Ведение документации, публикация промптов к генеративным моделям, воспроизводимый демонстрационный сценарий защиты.

## 4. Ожидаемый результат к декабрю 2026 года

Работающий прототип системы, разворачиваемый одной командой и демонстрируемый по заранее описанному сценарию:

1. **Эмулируемые трекеры на Linux** — условные драйверы модулей с переключением «эмуляция / железо», математические модели движения и физиологии, фильтр Калмана и прочие алгоритмы объединения, два канала связи с автоматическим переключением, буферизация при потере связи с последующей выгрузкой без дублей и пропусков, приём и подтверждение команд, реакция на кнопку SOS и индикация состояния через GPIO.
2. **Сервер** — PostgreSQL со схемой и миграциями, демо-батальон около 144 человек в сидах, приём телеметрии из двух каналов с дедупликацией, иерархия подразделений с рекурсивной видимостью и разграничением прав на шесть ролей, движок алертов, документированный REST API с OpenAPI-спецификацией, поток событий реального времени, отчёт о нагрузочном тестировании.
3. **Android-приложение** — релизный APK: единое приложение для всех уровней иерархии, карта с позициями, треками, геозонами и центроидом подразделения, карточка бойца с графиками показателей и расшифровкой оценки состояния, лента алертов с квитированием, push-уведомления по критичности, работоспособность без сети с индикацией давности данных, три темы оформления.
4. **Документация** — техническое задание, описание архитектуры, JSON-схемы пакетов телеметрии, OpenAPI-спецификация, дизайн-система с токенами и вайрфреймами, отчёты о тестировании (в том числе о качестве работы алгоритмов объединения: сравнение сырого и отфильтрованного трека) и опубликованные промпты к генеративным моделям.
5. **Публичный репозиторий** с равномерной историей правок и видимым вкладом каждого участника.
