# Демонстрация стенда: `make demo`

Одна команда поднимает стенд и **оставляет его работать**: вы отправляете кадры и сразу видите, что получил
брокер, что сказал edge и что сохранило приложение. Её может запустить любой в команде: она сама смотрит, что
есть на машине, запускает то, что можно, и не падает из-за того, чего нет. Как устроено — `ci/demo.py`;
как проверяется без показа — `make demo-check` (его же гоняет `make docker-check`).

## Что покажет на вашей машине

Выбирается автоматически; перед стартом печатается таблица «что будет запущено».

| Что есть | Что увидите |
|---|---|
| только `mosquitto` и `openssl` | брокер; кадры публикуются в него напрямую, как это сделал бы edge (режим `broker`) |
| + `qemu`, `zstd` и образ (`build/stand-bundle`; если его нет и `gh` авторизован, демо скачает сам, ~52 МиБ) | то же, но кадры идут через **настоящий edge в образе Linux**: видны `edge: published …` и `edge: dropped frame …` (режим `qemu`) |
| Linux и собранный edge (`make build`) | edge на этой машине вместо QEMU (режим `host`) |
| + запущенный Android-эмулятор и `adb` | ещё и **приложение**: строка `[userId], seq=N` в его логе на каждый принятый кадр |

Части независимы: можно без Android-SDK (всё, кроме приложения), и наоборот, без QEMU, но с эмулятором Android
(кадры идут в брокер напрямую, приложение получает их по MQTT; APK берётся из того же бандла, поэтому нужен `gh`).

Принудительно: `DEMO_EDGE=qemu|host|broker make demo`, `ANDROID=skip make demo`.

## Один раз подготовить машину

- Mac: `brew install qemu mosquitto zstd gh`, затем `gh auth login`. Linux: `apt install qemu-system-x86 mosquitto mosquitto-clients zstd`.
- Для приложения: Android Studio (или cmdline-tools), виртуальное устройство API 35 с `google_apis`
  (на Apple silicon образ arm64), запустить его; `adb devices` должен показать `emulator-5554   device`.
- Порт 8883 свободен.

## Запуск и команды

```text
make demo
demo> t                                  телеметрия с очередным seq
demo> t pulseBpm=130 temperatureX100=3900   свои значения (любые поля кадра: ключ=значение)
demo> b                                  битый кадр (версия 2): edge отбрасывает, брокер молчит
demo> n 5                                серия из 5 кадров
demo> s                                  что сейчас запущено
demo> q                                  выход; всё останавливается
```

После каждой команды печатается только новое: строка брокера (топик, размер и «совпадает с отправленным»),
строки edge и, если есть, приложения.

## Показ за 5 минут

1. `make demo`: покажите таблицу — что именно поднялось на этой машине.
2. `t`: кадр дошёл до брокера байт в байт, edge написал `published`, приложение сохранило его.
3. `t pulseBpm=130 temperatureX100=3900`: те же значения, но свои. Приложение хранит их, а на карте экрана
   могут перекрываться данными имитатора (`CI.md`, «Полный стенд»): достоверный признак приёма — строка в логе.
4. `b`: edge пишет `dropped frame: unsupported LMash version 2`, на брокере ничего нового.
5. `n 5`, затем `q`.

Намеренно **нет** команды «короткий кадр»: edge не ресинхронизируется по потоку UART, и такой кадр
испортит все следующие (`docs/TESTING.md`, «Ограничение»).

## Безопасность

- Брокер слушает только `127.0.0.1` (гость QEMU и эмулятор Android ходят на него через `10.0.2.2`). Брокеры
  `make e2e`, `make fullstand` и `stand.yml` пока слушают все интерфейсы; для демо это закрыто переменной `STAND_BIND`.
- Приложение трогается **только на эмуляторе** (`emulator-NNNN`): `pm clear` стирает данные приложения, телефон
  демо не берёт даже если он подключён.
- Всё временное лежит в `/tmp/mes-demo-*` и убирается при выходе, по Ctrl-C и по SIGTERM: брокер, QEMU, pty,
  приложение. Повторный запуск не находит ничего занятого.
- Пароли тестовые (`emulator/stand/stand.env`), сертификаты на 1 день. В репозиторий демо пишет только скачанный
  `build/stand-bundle`.
- Если edge или приложение не поднялись, демо говорит об этом и продолжает в более простом режиме, а не падает.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| `port 8883 is already in use` | уже идёт другой стенд или брокер: `lsof -nP -iTCP:8883`, остановите его |
| `нет mosquitto …` | поставьте брокер и клиенты (см. выше); на Mac демон лежит в `/opt/homebrew/sbin`, демо ищет его там само |
| `образа нет, а gh не авторизован` | `gh auth login` и снова `make demo`, либо `make fullstand` один раз |
| `edge … не поднялся` | причина в сообщении; демо продолжит без edge, кадры пойдут в брокер напрямую |
| `приложение не запустилось` | проверьте `adb devices` и что эмулятор загрузился; демо продолжит без приложения |
| зависло на «загружаю образ» | QEMU без KVM (всегда на Mac) грузится медленнее; ждёт до 3 минут |

## Что проверено, а что нет

Проверено (Mac, Apple silicon, и контейнер `ubuntu:24.04`): режимы `broker`, `qemu` и `host`, меню, ошибки ввода,
занятый порт, возврат в простой режим при сбое edge, скачивание бандла, уборка после Ctrl-C/SIGTERM, привязка
брокера к `127.0.0.1`. **Не проверено: часть с приложением** — на машине, где писался демо, нет Android SDK.
Выбор эмулятора покрыт юнит-тестом (`ci/test_demo.py`), сам запуск приложения повторяет проверенный в `stand.yml`
код. Кто первым запустит `make demo` с эмулятором, допишите сюда результат.
